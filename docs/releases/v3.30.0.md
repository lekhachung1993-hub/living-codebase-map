# LCM v3.30.0 — Evidence-First Operational Memory

This release completes phases 25–30 of the current roadmap while keeping LCM independent from any architecture modeling standard.

## What changed

- Structured constraints now use schema v2 and remain semantically aligned with both Markdown map projections.
- Index schema v4 and graph schema v2 attach knowledge type, provenance, and freshness to generated evidence.
- File-hash caching makes repeated updates incremental without changing deterministic output.
- Context compilation ranks evidence by architectural scope, risk, relationship, and freshness.
- New `scripts.lcm_core` modules establish stable boundaries for schemas, evidence, semantics, incremental indexing, and interoperability.
- Optional `calm-export` and `calm-reconcile` commands support declared-versus-observed architecture workflows without adding a CALM runtime dependency.
- The benchmark harness now states its proof boundary explicitly: fixtures and scoring are not substituted for recorded agent runs.

## Compatibility

- Core CLI remains Python 3.8+ standard-library only.
- Constraint schema v1 is migrated to v2 when loaded.
- CALM integration is opt-in; standalone LCM behavior remains the default.
- `.lcm/cache.json` is a disposable local acceleration artifact and is not committed.

## Release gates

The release is accepted only when unit tests, bytecode compilation, JSON parsing, semantic map checks, strict fitness checks, editable installation, incremental reuse, and CALM export/reconciliation all pass from the release tree.

External A/B benchmark evidence remains a separate operational campaign. No unrecorded performance claim is made by this release.
